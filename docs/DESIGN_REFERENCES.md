## 十项比较

下表是基于上述文件对 **Aegis 适配性的设计判断**，不是品牌产品实测评分。数字、图表和长期舒适度未被这些文件完整验证，不编造它们已有的规范。

| 维度 | Linear 参考 | Vercel 参考 | Supabase 参考 |
| --- | --- | --- | --- |
| 信息密度 | 层次清晰；营销间距需收紧 | 对齐可用；大段留白需删除 | 分组适合；工程细节需隐藏 |
| 深色模式 | 最接近目标，但底色需提亮 | 需原创适配，不能简单反色 | 深色面板可参考，不能视作全套深色规范 |
| 数字展示 | 未给完整计量规则 | 等宽文字思路有用；精度规则另定 | 需另定单位和精度 |
| 卡片结构 | 适合作为主参考 | 适合结构分隔 | 适合分组，去掉叠层 |
| 状态颜色 | 少色原则可用，六状态需自定 | 借鉴语义角色，不导入全部色阶 | 借鉴图表色和系统色区分 |

## Aegis 原创转化

产品语言：**清晰额度，安静足迹。** 依据用户的“简洁、方便、使用留下痕迹”目标，形成以下原创决定：

- 石墨背景、两层内容表面、单一冷蓝交互强调；语义色独立于强调色。
- 四 Provider 固定位置，三张额度卡加一张余额卡；保持认知一致，允许真实字段不对称。
- 5h 剩余/余额是主数值，Weekly 是第二层；采集时间永远是该卡自己的时间。
- 额度条回答“还剩多少”；足迹回答“什么时候观察到变化”；两种视觉不得互相冒充。
- Token 来源未验证时，只给明确空态。真实计数接入后才出现已记录累计与里程碑；不提供“消耗越多越好”的奖励反馈。
- 所有规则在根目录 [DESIGN.md](../DESIGN.md) 定义；不要求施工 Agent 再去猜品牌风格。

本轮额外发现并修正文档歧义：原 #354151 边线相对卡片底色只有约 1.56:1，不足以承担需要 3:1 对比度的交互边界。保留它作为装饰分隔线，增加独立 control-border；同时明确字体 DIP 与 pt 的换算，避免施工时字号放大 4/3。

对齐结果：保留方案 A、900×600 / 760×560 DIP、2×2 卡片、PySide6、SQLite、三批施工和数据真实性边界。静态设计板保持原样，仍只是布局草图；新增交互态与精度规范以 DESIGN.md 为准。
